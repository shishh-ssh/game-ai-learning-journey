# P1-M1：游戏世界、工具契约与评测

## 项目问题

LLM 可以生成看似合理但实际上不存在的物品、地点或任务进度。项目首先需要一个独立于模型的确定性世界，负责保存真实状态、校验工具调用并判断任务是否完成。

## 首个固定任务

玩家要求 NPC 将仓库中的药品送给森林哨站的受伤侦察员。

初始世界：

- NPC 位于村庄；
- 药品位于仓库；
- 受伤侦察员位于森林哨站；
- NPC 尚未检查仓库，也不知道药品是否存在；
- 任务状态为 `accepted`。

成功轨迹至少需要：

1. 移动到仓库；
2. 检查仓库；
3. 取得药品；
4. 移动到森林哨站；
5. 将药品交给受伤侦察员。

## 两类状态

### World State

世界中的客观事实，例如：角色位置、物品位置、物品所有者、任务进度。它只能由合法的世界规则更新。

### Agent Memory

Agent 已观察或被告知的信息。它可能不完整、过期或错误，不能直接覆盖 World State。

例如，药品实际位于仓库，但 NPC 尚未检查仓库：

- World State：药品位于仓库；
- Agent Memory：尚无药品位置记录。

## 第一组工具

| 工具 | 参数 | 合法条件 | 世界变化 |
| --- | --- | --- | --- |
| `move` | `destination` | 目的地存在且可达 | 更新 NPC 位置 |
| `inspect` | `target` | 目标与 NPC 位于同一地点 | 返回观察并写入 Memory |
| `take_item` | `item` | 物品与 NPC 位于同一地点 | 物品进入背包 |
| `give_item` | `item`, `character` | NPC 持有物品且与角色同地 | 更新物品所有者和任务进度 |

## 第一版评测

- `task_success`：药品是否交给正确角色；
- `invalid_tool_calls`：违反前置条件的工具调用次数；
- `state_consistency`：物品是否同时出现在多个位置或所有者中；
- `steps`：完成任务使用的工具调用数；
- `memory_grounded`：Memory 中的信息是否来自观察或明确输入。

## 当前实现顺序

1. 定义 World State；
2. 定义工具输入和前置条件；
3. 实现确定性工具执行；
4. 使用固定动作序列完成任务；
5. 建立评测器；
6. 最后才接入 LLM planner。
